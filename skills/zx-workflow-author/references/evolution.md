# Composition Evolution

Evolution improves this skill's decisions about generated workflows; it does not create another
published skill or a task-specific solver.

Evaluate composition policies across independent problem families. Measure at least correctness,
gate coverage, context isolation, skill relevance, rollback, determinism, token use, latency, and
secret safety. Freeze the baseline, tools, models, dependencies, task digests, and budgets.

Count authoring plus every generated producer, reviewer, repair, and retry call. A comparison has
complete cost coverage only when every assistant ledger entry exposes structured usage. Keep cached
input as a subset of input, preserve per-call records for long-context pricing, and report missing
coverage instead of imputing a favorable cost.

Use development evidence to diagnose and change one explicit composition behavior: stage boundary,
context budget, skill route, agent route, gate, reviewer, retry, or recovery rule. Freeze one selected
candidate before sealed validation. Validation accepts or rejects only; its failures must not tune the
same study. Preserve protected metrics and require a new study for later mutations.

Translate declared evaluation budgets into executable plan limits. A runtime must count all nested
producer and reviewer calls, cap process time by the remaining global wall budget, and stop after a
metered token limit is crossed. Budget exhaustion is a fail-closed terminal outcome, not retry
feedback. Compare quality and resource use together; never call an unbounded quality gain Pareto-safe.

Promote a learned rule into `SKILL.md`, a routed reference, the scaffolder, or runtime only when its
scope is general, its evidence spans multiple problem families, and offline regression tests encode
the observable invariant. Keep benchmark data and evaluation machinery outside the product catalog.
